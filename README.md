# 白酒终端巡检工具（ShelfGuard）

微信小程序，用于白酒终端门店陈列巡检，支持水印拍照、AI 智能分析、巡检记录管理。

## 功能特性

### 已完成功能

#### 1. 水印相机页面
- 实时预览水印（任务名称、门店、业务员、位置、时间）
- 支持三种水印位置：底部、顶部、全屏平铺
- 前后摄像头切换、闪光灯控制
- 设置面板（可编辑任务、门店、业务员信息）
- Canvas 高清水印合成

#### 2. 上传页面
- 多图支持（横向滚动预览）
- 智能压缩（渐进式压缩到 600-800KB）
- 压缩/上传进度展示
- 错误重试机制
- 自动触发 AI 分析

#### 3. AI 分析云函数
- 支持 OpenAI GPT-4o 和通义千问 VL
- 结构化分析：评分、总结、产品识别、问题、建议
- 未配置 API Key 时返回模拟报告
- 分析结果自动保存到数据库

#### 4. 报告详情页
- 状态栏展示（分析中/完成/失败）
- 圆形评分展示
- 产品列表、问题列表、建议列表
- 自动轮询刷新（分析中状态）
- 支持手动刷新和重试

#### 5. 历史记录页
- 统计卡片（总巡检、平均分、本周）
- 搜索功能（门店/任务名称）
- 筛选功能（时间范围、评分范围）
- 缩略图 + 评分 + 摘要展示
- 下拉刷新 + 分页加载

#### 6. 全局优化
- CSS 变量设计系统
- 统一错误处理和用户提示
- 全局状态管理（用户信息、当前任务）
- 工具函数抽离（date、compress、auth、validator、format）

## 技术栈

- 微信小程序原生开发
- 微信云开发（CloudBase）
- Canvas 2D 水印合成
- AI 视觉模型（GPT-4o / 通义千问VL）

## 快速开始

### 1. 配置项目

1. 打开 `project.config.json`，替换 `appid` 为你的小程序 AppID
2. 打开 `miniprogram/app.js`，替换 `cloudEnv` 为你的云开发环境 ID

### 2. 开通云开发

1. 在微信开发者工具中点击「云开发」按钮
2. 开通云开发，创建环境
3. 在云开发控制台创建数据库集合：
   - `inspections` — 巡检记录
   - `users` — 用户信息

### 3. 部署云函数

右键每个云函数目录，选择「上传并部署：云端安装依赖」。

### 4. 配置 AI 视觉 API（可选）

编辑 `cloudfunctions/analyzeImage/index.js`：

```javascript
// 设置环境变量（在云函数环境变量中配置）
OPENAI_API_KEY=your-openai-key
DASHSCOPE_API_KEY=your-dashscope-key

// 选择使用的模型
const CURRENT_MODEL = 'openai'  // 或 'qwen'
```

未配置 API Key 时，系统会返回模拟报告，方便测试。

## 本次新增：拍照拼图 + 客户管理 + 就近选客户

### 1. 拍照拼图（1~6张）
相机页支持连拍最多 6 张，拍完点"完成"：只拍 1 张时跳过拼图直接走原来的单图水印流程；拍了多张会先用 `photo-grid-canvas` 组件把几张图按固定网格布局（1/2/3 张一行，4/5/6 张两行）拼成一张大图，再对这张拼好的大图统一打一次水印。

**已知取舍**：拼成一张图之后，每张原图在最终图里只占一个格子，分辨率会被压缩，如果货架上文字/价签比较密集，AI 识别精度可能会比"多张原图各自全分辨率分析"要差。如果实测发现精度不够用，不需要重新开发——`analyzeImage` 云函数本来就支持一次传多张原图、AI 自动合并成一份报告（这个逻辑早就写好了），把"拼图"这一步跳过、把 `capturedPhotos` 数组原样传给上传流程即可切换回那条路径。

### 2. 客户管理（`customers` 集合 + 云函数 + 管理页面）
相机页设置面板"客户管理"入口，可以维护自己的客户资料（门店名、地址、联系人、电话、门店坐标）。**这是业务员私有数据**，跟 `products`（团队共享）的权限模型是反过来的，云函数强制按 `_openid` 过滤，业务员之间互相看不到对方的客户列表，详见 `DATABASE_SCHEMA.md` 里 `customers` 集合的权限说明。

### 3. 拍照时就近选客户
设置面板门店名称输入框旁边"📍从客户库选择"，点开会带上当前定位、按 Haversine 直线距离由近到远排好序（没填过坐标的客户排最后）。选中后自动回填门店名/地址，客户的 `_id` 也会存进这次巡检记录的 `customerId` 字段，方便以后按客户查历史。

## 新增功能：产品库管理



在相机页"设置"面板里新增了"产品库"入口，可以录入自家品牌的产品资料（品牌名、产品线、别名、正/背/侧面参考照）。这份资料会被 `analyzeImage` 云函数自动查询并拼进 AI 分析的 Prompt，让品牌识别时有据可依（尤其是别名归一化，避免同一品牌因为叫法不同被 AI 统计成两个）。

设计上明确了两种不同的权限模型，写代码时要分清楚：
- `inspections`（个人巡检记录）：云函数必须按 `_openid` 过滤，只能查自己的。
- `products`（团队共享产品库）：云函数**不**按 `_openid` 过滤，全员看到同一份数据，`_openid` 只做审计用途。

当前版本没有做角色权限限制（任何登录用户都能维护产品库），这是"先跑起来"的简化设计，后续要收紧的话在 `cloudfunctions/products/index.js` 里加一次角色校验即可。详见 `DATABASE_SCHEMA.md` 里的 `products` 集合说明。

## 如何把自己设为管理员（admin）

出于安全考虑，`role` 字段不允许通过小程序端自己修改（`login` 云函数的更新白名单里特意没放这个字段，否则任何人都能把自己改成 admin，等于没做权限控制）。设置方法：

1. 用你自己的账号在小程序里正常登录一次、并在相机页"设置"面板里填一下姓名（这一步会在 `users` 表里创建你的用户记录，默认 `role: 'sales'`）。
2. 打开微信开发者工具 → 云开发控制台 → 数据库 → `users` 集合，找到 `_openid` 是你自己的那条记录（可以用姓名或手机号定位）。
3. 把这条记录的 `role` 字段手动改成 `"admin"`，保存。
4. 重新打开一次小程序（触发重新登录），"巡检记录"页就会多出"按业务员筛选"的入口，此时你能看到全部业务员的记录；其他没被设为 `admin`/`manager` 的账号还是只能看自己的。

## 本次新增：管理者视角（按业务员查看/筛选）

- `getHistory` 云函数重构：角色永远从服务端 `users` 表按 `_openid` 查出来，不信任客户端传的任何角色声明。`role` 为 `sales`（默认）的账号，无论传什么筛选参数，服务端都强制只返回自己的记录；`role` 为 `admin`/`manager` 的账号可以看全部业务员的记录，也可以传 `targetUserName` 只看某一个人的。
- 新增 `action: 'stats'`：历史页的统计卡片（总数/本周/平均分）原来是前端直接查数据库，会被数据库"仅创建者可读写"的安全规则卡住，管理者也看不到全员汇总；现在改成走云函数，跟列表查询共用同一套角色判断逻辑。
- 历史页新增"业务员"筛选（仅 `isManager` 为 `true` 时显示），管理者可以输入姓名只看某个业务员，留空则看全部。

## Bug 修复记录（本次）

- 🔴 **[安全] `getHistory` 云函数补上 `_openid` 过滤**：修复前任意登录用户可查询到全部用户的巡检记录（云函数以管理员权限运行，会绕过数据库安全规则）。
- 🟠 **[崩溃] 相机页 `confirmPhoto` 位置为空时崩溃**：定位失败/被拒绝时不再直接访问 `location.latitude`，改为弹窗让用户选择"不带位置继续"或"重新定位"。
- 🟠 **[竞态] 水印合成组件挂载时序问题**：`<watermark-canvas>` 不再用 `wx:if` 控制显隐（`setData` 异步导致拍照后立即调用可能选不到节点），改为常驻挂载、组件内部用 CSS 移出屏幕隐藏。
- 🟠 **[架构] 多图巡检的 AI 分析结果互相覆盖**：`analyzeImage` 改为一次性接收该次巡检的所有 `fileIDs`，合并成一次 AI 调用、产出一份综合报告，不再按张循环调用导致后面的结果覆盖前面的、且浪费 AI 调用成本。
- 🟡 `login` 云函数为用户信息更新增加字段白名单（`name`/`phone`/`department`），避免任意字段被写入数据库。
- 🟡 相机页接入 `utils/location.js`（带权限引导弹窗）和 `utils/validator.js`（基础信息校验），去除重复实现的定位逻辑。
- 🟡 报告页轮询超时后给出提示，而不是静默停止。
- 🟡 `DATABASE_SCHEMA.md` 中 `aiReport` 字段结构改为与 `analyzeImage` 云函数实际输出保持一致。

> 模型切换说明：当前 `analyzeImage` 默认走 `openai`（GPT-4o）分支，`qwen` 分支已预留并支持多图；后续切到通义千问 qwen3.7-plus 时，只需改 `CURRENT_MODEL` 并核对 `AI_CONFIG.qwen` 里的 `model` 名称和请求体格式（不同千问模型的多模态接口字段可能有差异，接入前建议对照官方文档核实一次），主流程不需要改动。
