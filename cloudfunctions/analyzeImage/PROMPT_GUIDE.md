# Prompt 优化建议

改的对象是 `cloudfunctions/analyzeImage/prompt.js`。下面每条都写清了「现状 → 问题 → 怎么改」，
带 ✂️ 的段落可以直接复制粘贴进 prompt.js。改完记得重新上传部署 `analyzeImage` 云函数。

排序按我认为的性价比，从高到低。

---

## 已经替你改掉的两处（不用你动手）

1. **JSON 示例加了「仅为格式模板」的警告**。原来的示例里写着"五粮液 / 85分 / 95%以上产品正标朝外"，
   大模型有很强的**锚定效应**，会不自觉地照抄示例里的品牌和分数——货架上明明没有五粮液，报告里也可能冒出来。
   现在明确告诉它这些数值是虚构占位。
2. **删掉了 `metadata.analysisTime`**。让模型输出当前时间是没有意义的（它不知道现在几点，只能编），
   而且数据库里已经有 `analyzedAt` 服务器时间了。
3. **加了第 8 条规则「不要编造看不清的信息」**，这是视觉模型最常见的失败模式。

## 建议 1（强烈推荐）：引入「本品牌」立场，别做中立裁判

**现状**：Prompt 把 AI 设定成一个中立的行业专家，竞品分析只是罗列各品牌占比。

**问题**：这不符合实际业务。用这个小程序的是**某个白酒品牌的业务员**，他关心的不是"这个货架整体好不好"，
而是"**我的酒**在这个货架上混得怎么样、比竞品差在哪"。现在报告读下来像一份行业调研，
业务员看完不知道自己该干嘛。这是当前 Prompt 最大的商业价值缺口。

系统里其实已经有数据支撑了——`products` 集合存的就是"本品牌"产品资料，
`analyzeImage` 每次分析都会把它拼进 Prompt。只是 Prompt 没告诉 AI「这些是你的自己人」。

**怎么改** ✂️ 在 `SYSTEM_PROMPT` 的「## 评估维度与标准」之前插入：

```
## 你的立场（重要）

user prompt 末尾会附上一份「本品牌产品资料」。那些品牌是**我方品牌**，其余全部视为竞品。
你的报告是写给我方业务员看的，因此：
- 所有评估优先围绕"我方品牌在这个货架上的表现"展开
- 问题和建议必须落在"业务员当场能动手改"的层面（调正标、补价签、抢位置、理货）
- 不要写"建议该门店优化整体品类结构"这种业务员管不着的话
- 如果画面里完全没有我方品牌，在 summary 第一句就明确说出来，并把这件事列为 high 级别 issue
```

同时在输出 JSON 里加一个 `ownBrandPerformance` 段 ✂️：

```json
  "ownBrandPerformance": {
    "present": true,
    "brands": ["<我方品牌名>"],
    "facingCount": 6,
    "facingSharePercent": 22,
    "bestPosition": "中层中部",
    "vsTopCompetitor": "排面比第一竞品少 8 个，且位置偏低一层",
    "verdict": "劣势"
  },
```

`verdict` 取值建议限定为：`领先` / `均势` / `劣势` / `缺席`。

> ⚠️ 加了新字段，前端不会自动显示。要在 `miniprogram/pages/report/report.wxml` 里
> 加一段对应的渲染卡片才能看到。

## 建议 2（强烈推荐）：把评分从「感觉」变成「算出来的」

**现状**：Prompt 列了 7 项权重，但只是描述性地写在那里，没要求 AI 真的去算。

**问题**：两个硬伤。
- 第一，权重表里的「产品识别完整度 15%」在输出结构里**根本没有对应的分项**，
  另外 6 项加起来只有 85%，AI 无从下手，只能拍脑袋给个总分。
- 第二，同一张照片跑两次，分数经常差 8-15 分。因为总分是"感觉出来的"，不是算出来的。
  分数不稳定，业务员之间的横向对比和月度趋势统计就全废了。

**怎么改** ✂️ 把「评分权重」那一段整体替换成：

```
评分权重（必须严格按此计算，不允许凭感觉给总分）：

| 维度 | JSON 字段 | 权重 |
|------|-----------|------|
| 正标朝向 | labelOrientation | 25% |
| 整齐度 | neatness | 20% |
| 黄金位置利用 | goldenPosition | 20% |
| 集中陈列 | brandConcentration | 15% |
| 价签对应 | priceTagMatch | 15% |
| 货架饱满度 | shelfFullness | 5% |

计算步骤（必须按顺序执行）：
1. 先给 6 个维度各自打 0-100 分，写进 displayCompliance
2. 再按上表权重加权求和：score = 0.25×labelOrientation + 0.20×neatness +
   0.20×goldenPosition + 0.15×brandConcentration + 0.15×priceTagMatch + 0.05×shelfFullness
3. 四舍五入取整，写进 score 字段
4. score 必须等于第 2 步的计算结果，不允许另外给一个"感觉分"
```

注意我把「产品识别完整度」从权重表里拿掉了——识别得全不全是**模型自己的能力问题**，
不是**门店陈列的质量问题**，拿它扣店里的分本身就不合理。

再配合把 `index.js` 里的 `temperature` 从 `0.2` 降到 `0.1`，分数波动能明显收窄。

## 建议 3（推荐）：把位置描述改成九宫格，掐死幻觉

**现状**：示例里写「第3排第2个位置缺少价签」。

**问题**：视觉模型数不清"第几排第几个"。这类精确坐标基本全是编的，
业务员按图索骥找不到地方，几次之后就不信任报告了。假装精确比模糊更有害。

**怎么改** ✂️ 在「## 重要规则」里追加：

```
9. **位置一律用九宫格描述**，不要用"第X排第Y个"这种精确坐标。
   纵向只分：上层 / 中层 / 下层；横向只分：左侧 / 中部 / 右侧。
   例如"中层右侧"、"下层左侧"。看不出层次的画面就写"画面右侧"。
10. **数量表述允许模糊**。排面数、产品总数如果数不清，
   用区间表达（如 "3-5"）或直接给 null，不要硬凑一个精确数字。
```

同时把 System Prompt 里 issues 示例的 `"第3排第2个位置缺少价签"` 改成 `"中层右侧约2个位置缺少价签"`。

## 建议 4（推荐）：加「不可评估」出口，别让废片污染统计

**现状**：照片糊了、拍到的不是货架、光线太暗，一律返回 `score: 0`。

**问题**：`getHistory` 算团队平均分时会把这些 0 分算进去，一张废片能把平均分拉低好几分。
"分析失败"和"陈列真的很差"在数据上是两回事，不该混在一起。

**怎么改** ✂️ JSON 输出顶层加字段：

```json
  "evaluable": true,
  "notEvaluableReason": "",
```

规则里追加：

```
11. **evaluable 字段**：当照片模糊到看不清标签、画面主体不是酒类货架、
    严重过曝/欠曝导致无法判断时，evaluable 设为 false，
    在 notEvaluableReason 里说明原因，score 给 0，
    其余分析字段给空数组/空对象即可，不要强行分析。
```

然后在 `cloudfunctions/getHistory/index.js` 计算平均分的地方，
把查询条件从 `{'aiReport.score': _.exists(true)}` 改成
`_.and({'aiReport.score': _.exists(true)}, {'aiReport.evaluable': _.neq(false)})`，
把不可评估的记录排除掉。

## 建议 5（可选）：给分数打「锚点」，让不同门店可横向比较

**现状**：只有一张"90-100 卓越 / 80-89 优秀"的档位表，描述很抽象。

**问题**：模型对"优秀"的理解每次都可能不一样。缺少具体锚点，跨门店的分数就没有可比性。

**怎么改** ✂️ 在评分标准表格下面补锚点描述：

```
分数锚点（用来校准你的判断尺度）：
- 92 分长什么样：全部产品正标朝外无一例外，横向对齐成一条直线，
  品牌完整成块，每个 SKU 都有清晰对应的价签，货架无空位
- 75 分长什么样：绝大部分正标朝外但有 2-3 瓶歪斜，间距略有不均，
  品牌基本成块但边缘混入 1-2 个其他品牌，个别价签缺失
- 55 分长什么样：超过三成产品正标未朝外或倒置，排列明显参差，
  同品牌被拆散在两处，价签缺失过半或明显错位
- 35 分长什么样：产品随意堆放，无陈列逻辑，大面积空位或倒瓶
```

三四个锚点就够，给太多反而稀释注意力。

## 建议 6（可选）：多图去重给出判定依据

**现状**：只说了"注意跨图片去重（同一产品出现在多张照片中不要重复计数）"。

**问题**：没告诉 AI **怎么**去重。实际相机页最多拍 6 张会拼成一张网格大图再上传，
所以模型看到的是一张"图中有多个分格"的图，更容易把同一个 SKU 数两遍，排面数虚高。

**怎么改** ✂️ 在 `buildUserPrompt` 的多图分支里补一句：

```
去重判定标准：如果同一款酒（品牌+产品线+瓶型完全一致）在多个画面/分格中出现，
以能看清最多排面的那一个画面为准计数，其余画面视为同一位置的不同角度，不重复累加。
如果无法确定是否为同一位置，按"是同一位置"处理（宁可少算，不要多算）。
```

另外提醒一句：因为上传的常常是**拼图后的网格大图**，最好在 user prompt 里明说
"这张图可能由多个分格拼接而成，每个分格是同一货架的不同角度"，否则模型可能把网格线
当成货架隔板，`shelfCount` 会数错。

## 建议 7（可选）：让建议带上「可核查的完成标准」

**现状**：`suggestions.action` 是"立即补充缺失的3个价签"，`expectedEffect` 是"提升购买转化率约15%"。

**问题**：那个 15% 是模型编的，没有任何依据。写进报告里看着专业，实际上是噪音，
时间长了会让人对整份报告的可信度打折。

**怎么改**：把 `expectedEffect` 换成 `verifyBy`（下次巡检怎么验证这条做没做到）✂️：

```json
  "suggestions": [
    {
      "priority": "high",
      "action": "补齐中层右侧缺失的价签",
      "verifyBy": "下次巡检时中层每个SKU下方均可见价签",
      "deadline": "当日"
    }
  ]
```

如果舍不得 `expectedEffect`，至少在规则里加一句：
「expectedEffect 只描述定性效果，禁止编造具体百分比数字」。

> ⚠️ 改字段名要同步改 `report.wxml` 第 190 行的 `item.expectedEffect`。

## 建议 8（可选）：Prompt 太长了，可以砍

**现状**：System Prompt 约 2400 字，其中 JSON 示例占了一半以上。

**问题**：Qwen-VL-Plus 的注意力是有限的，输入越长，对**图片**的注意力占比越低。
而且每次调用都要重复计费这 2400 字（虽然文本 token 比图片便宜得多）。

真正在起作用的是「评估维度」「评分标准」「输出格式」三块。
"你的专业背景"那 4 条对输出质量的影响其实很小——模型本来就知道茅台五粮液是什么。

**怎么改**：如果发现分析结果对图片细节不敏感（比如明明有明显问题却没指出来），
可以试着把「## 你的专业背景」整段删掉，只留一句
「你是资深白酒终端陈列评估专家，熟悉主流白酒品牌、香型分类和终端陈列标准。」
对比一下效果，多半没有变差。

JSON 示例可以把 `productIdentification`、`brands`、`issues`、`suggestions` 这几个数组
各留 1 个元素就够（现在 issues 有 2 个、suggestions 有 3 个），模型照样知道是数组。

## 改完怎么验证

没有测试脚本的话，最土但最有效的办法：

1. 找 3 张有代表性的照片：一张明显规范的、一张明显混乱的、一张模糊废片
2. 每张连跑 3 次，记录 `score`
3. 看两件事：
   - **同一张图 3 次的分差**，超过 8 分说明还不够稳，回去看建议 2
   - **规范图和混乱图的分差**，小于 20 分说明模型没有真的在区分，尺度太挤，回去看建议 5

在小程序「设置 → 立即分析待处理记录」里手动触发，比等定时任务快。
